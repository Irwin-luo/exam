# 项目规则 · exam-registration-app

AI 在本项目中生成或修改代码时，必须遵循以下规则：

## 1. 模块化

- 按功能域组织代码，报名相关逻辑统一放在 `src/features/registration/` 下（components / data / utils / db / types 分层）。
- 单个文件、单个函数只承担单一职责；可复用的字段配置、选项常量、类型定义、工具函数必须抽取到独立模块，不要在页面或组件中内联大段重复逻辑。
- 页面组件（`src/app/**`）只负责页面编排，业务逻辑下沉到 feature 模块。

## 2. 保留测试

- 不得删除、跳过或弱化已有测试（`src/features/registration/__tests__/`）。
- 修改功能时必须同步更新或补充对应测试，新增逻辑必须有测试覆盖，确保 `npm test` 始终通过。
- 修复缺陷时先复现（可先补一个失败用例），再修复，最后用测试证明。

## 3. 避免无关改动

- 只修改与当前任务直接相关的文件，保持改动范围最小，不顺手做无关重构、格式化或重命名。
- 不删除题目无关文件；不随意升级依赖、不改动构建与配置文件，除非任务明确要求。
- 每次改动后通过 `npm run lint`、`npm test`、`npm run build` 验证，确保不破坏现有功能。
