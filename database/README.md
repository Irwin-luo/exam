# SQLite 数据库考试素材

本目录提供 Trae Code 实操认证中的 SQL 重构与查询优化素材。它不是生产级数据库设计，而是专门为考试准备的“低质量初始版本”，用于让考生识别问题并提出优化方案。

## 文件说明

| 文件 | 作用 |
|---|---|
| `schema.bad.sql` | 初始 SQLite 表结构，故意包含命名混乱、缺少约束、缺少索引等问题 |
| `seed.sql` | 种子数据，故意包含重复报名、空手机号、非法邮箱、状态值不统一等脏数据 |

## 建议考察方向

考生可从以下方面分析和优化：

1. 主键与唯一约束；
2. 必填字段与 CHECK 约束；
3. 角色、状态、场次的枚举或关联表设计；
4. 重复报名规则，例如 `phone_no + sessionName`；
5. 字段命名统一；
6. 时间字段格式统一；
7. 索引设计；
8. `SELECT *` 查询优化；
9. 字符串拼接 SQL 的注入风险；
10. 数据清洗与迁移策略。

## 可选本地验证方式

如果电脑安装了 SQLite CLI，可以在项目根目录执行：

```bash
sqlite3 exam.db < database/schema.bad.sql
sqlite3 exam.db < database/seed.sql
sqlite3 exam.db "SELECT * FROM registrations;"
```

本项目默认不强制依赖 SQLite 运行时。考试重点是 SQL 设计、查询优化和数据访问层重构，避免因为本地原生依赖安装失败影响考试。

## 建议优化目标

一个合格的优化方案通常应包含：

- `registrations` 表设置明确主键；
- 把场次拆成 `sessions` 表；
- 把报名记录与场次用 `session_id` 关联；
- 对手机号、场次组合增加唯一约束；
- 对查询高频字段增加索引；
- 统一时间字段为 ISO 字符串或 Unix 时间戳；
- 查询时明确字段，不使用 `SELECT *`；
- 使用参数化查询，不拼接用户输入。
